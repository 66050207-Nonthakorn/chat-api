# รายการเตรียมพร้อมและรายละเอียดที่ต้องยืนยัน

> ฉบับละเอียดก่อนย่อ Notion เก็บเมื่อ 2026-10-28
> เอกสารแผนและข้อสรุป ไม่ใช่หลักฐานว่าพัฒนา ทดสอบ หรือ deploy สำเร็จ
> ที่มา: [หน้า Notion](https://www.notion.so/4037668803008138898fd32da9a5eb84) — ปัจจุบันเป็นฉบับย่อ

**สถานะ: เตรียมและพัฒนาบน local ได้ การสมัคร AWS และสร้างทรัพยากรเลื่อนไปภายหลัง**
ปรับปรุงเมื่อ 2026-10-25 ข้อสรุปหลักอยู่ใน [ข้อสรุปการออกแบบและงานที่เลื่อนไประยะถัดไป](03-decisions-and-deferred-work.md) หน้านี้มีเฉพาะรายละเอียดที่ยังต้องระบุ ไม่ย้อนเปิดทางเลือกที่ตกลงแล้ว

## ก่อนสร้างทรัพยากร AWS

- [ ] เจ้าของสมัคร AWS Free account plan เมื่อพร้อม และเปิด MFA ของ root
- [ ] ตรวจยอดเครดิต วันหมดอายุ บริการ/ฟีเจอร์ที่อนุญาต สิทธิ์ IAM และ quota ไม่ถือว่าได้รับเครดิตแล้วก่อนสมัคร
- [ ] ยืนยันวันสาธิต จำนวนคนทำ และเวลานำเสนอ ตารางหกสัปดาห์ยังเป็นข้อเสนอ
- [ ] เลือก region โดย Singapore เป็นสมมติฐานราคาเท่านั้น ตรวจราคา ชนิดเครื่อง และฟีเจอร์ของ region ที่เลือกจริง
- [ ] ตรวจสิทธิ์ใช้ Fargate, RDS PostgreSQL, ElastiCache แบบ node, ALB, NAT, Cognito, S3/CloudFront, secrets และ telemetry
- [ ] กำหนด DNS/ใบรับรอง และ HTTPS ระหว่าง CloudFront กับ ALB โดยไม่ซื้อโดเมนที่ยังไม่อนุมัติ
- [ ] กำหนดขนาดทรัพยากร engine/version ตำแหน่ง AZ จำนวน replica เพดาน autoscaling และ connection pool ฐานข้อมูลรวม
- [ ] ตรวจการใช้เครดิตประมาณการและเวลาทดสอบ เป้าหมายคือจ่ายเองใกล้ศูนย์ ไม่ได้อนุมัติงบเงินสด USD 50
- [ ] ตรวจ state backend และความปลอดภัย Terraform, OIDC role, วิธีตั้ง secret ครั้งแรก และแผนเก็บ/ล้างข้อมูลหลังจบ

ถ้าฟีเจอร์ต้องอัปเกรด Paid plan ให้หยุดขั้นสร้างทรัพยากรนั้นและเสนอทางเลือก ไม่เปลี่ยนสถาปัตยกรรมโดยไม่มีข้อสรุปจากเจ้าของ

## ก่อนกำหนด migration และสัญญาแกนข้อความ

- [ ] ระบุ schema, foreign key, index, คู่ผู้ใช้ DM ที่ไม่ซ้ำ ขอบเขต idempotency key และกฎ payload ที่ขัดแย้ง
- [ ] กำหนดลำดับการล็อกร่วมระหว่างจัดลำดับข้อความกับลบสมาชิก ทดสอบ race และ deadlock
- [ ] กำหนดผู้ถือ lease ของ outbox การหมดอายุ/คืนงาน retry/backoff บันทึกสำเร็จ cleanup และเหตุการณ์เสียที่ลองซ้ำไม่จบ
- [ ] ระบุ HTTP/event schema, cursor/pagination, ขนาด payload, rate limit, error คงรูป และ telemetry
- [ ] ระบุการรวม subscribe กับ catch-up การตรวจตามรอบ คิวที่จำกัด และ reconnect backoff

เป็นรายละเอียดการพัฒนาภายใต้หลักประกันที่ตกลงแล้ว ไม่ใช่การกลับมาเลือกฐานข้อมูลใหม่

## ก่อนใช้การยืนยันตัวตนจริง

- [ ] กำหนดอายุ/idle ของ session การเข้ารหัส token/กุญแจ refresh coordination, cookie/CSRF, Origin ที่อนุญาต และการจับคู่ตัวตนภายใน
- [ ] ระบุ logout เครื่องเดียว/logout ทุกอุปกรณ์ การตรวจ session ของ socket ที่เปิดค้าง และขอบเขตเวลาของการเพิกถอน
- [ ] ปิดสมัครสาธารณะ เตรียมหรือเชิญบัญชีเดโมขั้นต่ำ
- [ ] ตรวจว่า config/image บน AWS เปิดตัวตนจำลอง local ไม่ได้

คง Cognito และ backend-managed session ใน PostgreSQL ห้ามย้าย token ให้ JavaScript เพื่อเลี่ยงงานที่ต้องทำ โดยไม่ได้เปลี่ยนข้อสรุปกับเจ้าของ

## ก่อนตรวจรับเดโม

- [ ] ยืนยันผล baseline/stretch ตามจริง เกณฑ์ latency เชิงตัวเลขต้องมาจากข้อกำหนดและผลวัด ไม่แต่งขึ้น
- [ ] ตรวจ rolling deployment และ reconnect ด้วยไคลเอนต์ที่กำลังใช้งาน
- [ ] ตรวจ metric/alarm/trace sampling/log retention และไม่บันทึกข้อมูลอ่อนไหว
- [ ] ซ้อม scaling/failover ตามเครดิตและเวลา เตรียมหลักฐานบันทึกไว้สำหรับการทดลองช้า
- [ ] เก็บแผนภาพทรัพยากรจริงและเหตุผลเปรียบเทียบบริการ โดยตัดข้อมูลลับออก
- [ ] ส่งออกหลักฐานและตรวจ cleanup รวม snapshot และ storage ที่เหลือ

## ผู้ตัดสินใจและหลักฐานปัจจุบัน

เจ้าของต้องให้ข้อมูลเรื่องสิทธิ์บัญชี ตารางเรียน การอัปเกรดเสียเงิน การเปลี่ยนต้นทุนอย่างมีนัยสำคัญ บริการใหม่ หรือการลดหลักประกันที่ตกลงแล้ว ส่วนชื่อไฟล์ การจัดโค้ด ไลบรารีที่มีสัญญาเทียบเท่า และการทดสอบ local ใช้ดุลยพินิจภายในขอบเขตได้เมื่อได้รับคำสั่งให้พัฒนา

ปัจจุบันมีเอกสารและผลคำนวณราคาสาธารณะ ยังไม่ได้ยืนยันการทดสอบแอป CI deployment ทรัพยากร AWS เครดิต หรือประสิทธิภาพ ไม่ต้องสมัคร AWS ก่อนเริ่ม M1/M2 บน local
