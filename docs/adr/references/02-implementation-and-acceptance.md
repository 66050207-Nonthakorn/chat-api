ปรับปรุงเมื่อ 2026-10-25 สมัคร AWS ภายหลังได้ งาน local สองระยะแรกไม่ต้องรอบัญชี AWS

## วิธีทำงานและกรอบเวลา

ทำทีละส่วนที่รันและตรวจสอบผลได้ ตารางหกสัปดาห์ด้านล่างเป็นข้อเสนอ ไม่ใช่กำหนดส่งที่ตกลงแล้ว เพราะยังไม่ทราบวันนำเสนอ จำนวนสมาชิก และเวลาที่ทำงานได้ การจบระยะต้องมีหลักฐาน ไม่ใช่เพียงมีโฟลเดอร์ โค้ดโครง หรือเอกสาร

### สัปดาห์ 1 / M1 — แกนข้อความที่บันทึกถาวรบน local

**เงื่อนไขก่อนเริ่ม:** ตรวจ workspace และเครื่องมือจริง
**สิ่งส่งมอบ:** Go API, Docker Compose สำหรับ PostgreSQL/Valkey, migration, ข้อมูลตัวอย่างที่สร้างซ้ำได้, ตัวตนทดสอบเฉพาะ local, health endpoint, สัญญา HTTP ส่ง/อ่านข้อความ, ลำดับต่อห้อง และ transactional outbox

**เกณฑ์ตรวจรับ**

- [ ] เริ่มระบบใหม่ด้วยคำสั่งที่บันทึกไว้ได้ โดยไม่ใช้ AWS
- [ ] ผู้ไม่ใช่สมาชิกส่งหรืออ่านไม่ได้ และทดสอบการเปลี่ยนสมาชิกชนกับการเขียน
- [ ] ส่งพร้อมกันได้ลำดับต่อห้องที่ไม่ซ้ำและเพิ่มขึ้น
- [ ] ลองคำขอเดิมพร้อมกัน 100 ครั้งแล้วมีข้อความเชิงตรรกะเพียงหนึ่งรายการ ใช้รหัสเดิมกับเนื้อหาต่างกันต้องถูกปฏิเสธ
- [ ] ทำคำตอบ HTTP หายหลัง commit แล้วลองด้วยรหัสเดิม ต้องได้ผลของข้อความเดิม
- [ ] rollback แล้วไม่มีทั้งข้อความและ outbox
- [ ] แบ่งหน้าประวัติแล้วไม่มีรายการตกหล่นหรือซ้ำระหว่างหน้า
- [ ] restart API แล้วยังเรียกข้อความที่ยอมรับแล้วได้

**หลักฐาน:** integration test กับ PostgreSQL จริง คำสั่งและผลลัพธ์ รุ่น migration และวิธีเตรียมข้อมูล การ compile ผ่านอย่างเดียวไม่ถือว่าตรวจรับแล้ว

### สัปดาห์ 2 / M2 — ส่งสดข้ามอินสแตนซ์และหน้าจอขั้นต่ำ

**ขึ้นกับ:** M1
**สิ่งส่งมอบ:** คำสั่ง worker แยก, lease และ retry ที่กู้คืนได้, Pub/Sub ช่องร่วม, API สองอินสแตนซ์, WebSocket ที่ตรวจตัวตน, Svelte/TypeScript/Vite, cursor ต่ออุปกรณ์ และข้อความรอยืนยันใน IndexedDB

**เกณฑ์ตรวจรับ**

- [ ] บังคับให้ไคลเอนต์สองรายอยู่คนละ API อินสแตนซ์ ส่งผ่าน HTTP แล้วอีกฝ่ายได้รับสด
- [ ] ผู้ใช้เดียวหลายอุปกรณ์ได้รับเหตุการณ์ที่เหมาะสม และมีตำแหน่งกู้คืนแยกกัน
- [ ] หยุด worker ก่อน publish แล้วเริ่มใหม่ งานค้างต้องถูกทำต่อ
- [ ] หยุดหลัง publish แต่ก่อนบันทึกสำเร็จ เหตุการณ์ซ้ำต้องไม่สร้างข้อความซ้ำบนจอ
- [ ] worker หลายตัวและ lease หมดอายุไม่ทำให้งานถูกทิ้งถาวร
- [ ] ทำเหตุการณ์ Pub/Sub สุดท้ายหายโดยไม่ปิด socket การ sync ตามรอบต้องค้นพบ
- [ ] สลับลำดับเหตุการณ์ สร้างช่องว่าง และเชื่อมไปอีก replica แล้วประวัติต้องตรงกับฐานข้อมูล
- [ ] refresh ขณะไม่ทราบผลส่ง ต้องใช้รหัสที่บันทึกไว้เดิม ไม่สร้างคำขอเชิงตรรกะใหม่
- [ ] ผู้รับช้ามีคิวจำกัด ถูกตัดอย่างควบคุม และดึงข้อมูลคืนได้
- [ ] ปฏิเสธผู้ไม่ใช่สมาชิกทั้งการ subscribe และการส่งสด แม้พลาดเหตุการณ์แจ้งลบสมาชิก

**หลักฐาน:** ชุดทดสอบหลายไคลเอนต์ การสาธิตผ่านเบราว์เซอร์ การเทียบฐานข้อมูลกับไคลเอนต์ และอายุงาน outbox

### สัปดาห์ 3 / M3 — Cognito และ session สำหรับระบบจริง

**ขึ้นกับ:** M2 และบัญชี AWS Free ที่เจ้าของสมัครเมื่อต้องทดสอบ Cognito จริง เตรียมตัวแปลงจำลองสำหรับ local ก่อนได้
**สิ่งส่งมอบ:** Cognito แบบเชิญเท่านั้น บัญชีทดสอบ callback และ token ฝั่ง backend, session ใน PostgreSQL, cookie ปลอดภัย, การป้องกัน CSRF, การตรวจ Origin ของ WebSocket และกฎหมดอายุ/ออกจากระบบ

ก่อนเขียนสัญญา ต้องกำหนดอายุ session การเข้ารหัส token และกุญแจ การประสาน refresh และการตรวจ session ของ socket รายละเอียดเหล่านี้ยังเปิดอยู่ แต่ห้ามลดหลักประกันสิทธิ์ที่ตกลงไว้

**เกณฑ์ตรวจรับ**

- [ ] เข้าสู่ระบบจริงผ่าน Cognito แล้วจับคู่ issuer/subject ที่ตรวจแล้วกับผู้ใช้ภายในถูกต้อง
- [ ] JavaScript ส่วนหน้าไม่ได้รับ refresh token หรือ cookie ของ session ที่อ่านได้
- [ ] เรียกข้าม replica ได้โดยไม่ต้องอาศัย sticky session
- [ ] ปฏิเสธ session ที่ไม่ถูกต้อง หมดอายุ หรือถูกเพิกถอน และ Origin ที่ไม่อนุญาตตามสัญญาที่ระบุ
- [ ] รหัสผู้ใช้ที่ไคลเอนต์ส่งมาใช้ปลอมตัวเป็นผู้อื่นไม่ได้
- [ ] ข้อความค้างในเบราว์เซอร์ไม่ข้ามบัญชี และทดสอบการล้างเมื่อ logout
- [ ] เปิดตัวตนจำลองของ local บน AWS ไม่ได้

**หลักฐาน:** ผลทดสอบกับ provider จริงหลังสมัครบัญชี แยกผล mock ออกอย่างชัดเจน ไม่ใช้แทนการยืนยัน Cognito จริง

### สัปดาห์ 4 / M4 — สร้าง AWS environment สำหรับพัฒนาอย่างทำซ้ำได้

**ขึ้นกับ:** M3, ผลตรวจ local ผ่าน, ยืนยันสิทธิ์/เครดิตบัญชี region และเส้นทาง TLS
**สิ่งส่งมอบ:** Terraform และ state backend, IAM/security group, ALB สาธารณะ, task/ฐานข้อมูล/cache ใน private subnet, เส้นทางออก, ECR, RDS, ElastiCache, Secrets Manager, S3/CloudFront, CloudWatch/OTel และ GitHub OIDC

**เกณฑ์ตรวจรับ**

- [ ] ตรวจ Terraform plan ที่ระบุทรัพยากรมีค่าใช้จ่าย การแทนที่ ข้อมูลที่เก็บต่อ และคำสั่งล้าง
- [ ] สร้างภายใต้บริการที่ Free plan อนุญาตและเครดิตที่ตรวจจริงแล้วเท่านั้น
- [ ] เปิดเว็บจาก CloudFront/S3 และส่งข้อความผ่าน HTTPS/WSS บน AWS ไม่ใช่ [localhost](http://localhost)
- [ ] ไม่แคช API/auth ส่งต่อ cookie/header ถูกต้อง และ S3 ไม่เปิดสาธารณะ
- [ ] RDS/cache ไม่เปิดสาธารณะ จำกัดทางเข้า task และให้ IAM เท่าที่ต้องใช้
- [ ] โหลด secret ตอนรัน ไม่อยู่ใน source/image/log และป้องกันข้อมูลอ่อนไหวใน Terraform state
- [ ] task ใน private subnet ติดต่อ Cognito ดึง image อ่าน secret และส่ง telemetry ได้
- [ ] สร้างใหม่และล้างออกซ้ำได้ พร้อมรายการทรัพยากรและค่าใช้จ่ายที่ยังเหลือ

**หลักฐาน:** ผล plan/apply ที่ตัดข้อมูลลับ สถานะ task และ health, URL, ผลส่งข้าม task, แผนภาพตรงทรัพยากรจริง และรายการหลัง cleanup หากบัญชีใช้บริการไม่ได้ ให้หยุดขั้นนั้นเพื่อทบทวน ไม่เปลี่ยนสถาปัตยกรรมเงียบ ๆ

### สัปดาห์ 5 / M5 — CI/CD, rolling deployment และหลักฐานการกู้คืน

**ขึ้นกับ:** M4
**สิ่งส่งมอบ:** ตรวจ PR, สร้าง image/artifact ระบุเวอร์ชันแน่นอน, deploy พัฒนาอัตโนมัติเมื่อมี environment, เลื่อนเวอร์ชันไปสาธิตด้วยมือ, migration job, rollback, graceful shutdown, dashboard และสคริปต์จำลองความเสียหาย

**เกณฑ์ตรวจรับ**

- [ ] การเปลี่ยน main ที่ผ่านเงื่อนไขทดสอบ/build/deploy อัตโนมัติเมื่อมี environment หากไม่มีต้องแจ้งว่าข้าม ไม่สร้างขึ้นเอง
- [ ] การเลื่อนไปสาธิตใช้ digest และไฟล์ส่วนหน้าเดิมที่ผ่านการทดสอบ
- [ ] ไม่ deploy ชนกันใน environment เดียว และไม่ยกเลิก migration ที่กำลังทำโดยไม่พิจารณา
- [ ] รัน migration หนึ่งครั้งผ่านงานควบคุม และรองรับแอปเวอร์ชันเก่า/ใหม่ซ้อนกัน
- [ ] ส่งข้อมูลทดสอบระหว่าง rolling วัดข้อผิดพลาด การ reconnect การกู้คืน และข้อความที่ commit แล้ว
- [ ] deploy image/config ที่ตั้งใจให้เสีย แล้วแสดงการ rollback ตามขั้นตอน
- [ ] หยุด API/worker และขัดจังหวะ broker พร้อมเก็บหลักฐานงานค้างและการฟื้นตัว
- [ ] dashboard มีเวลา/ข้อผิดพลาดการตอบรับ socket ที่ใช้งาน อายุ outbox และ retry, broker failure, การ sync, CPU/memory และแรงกดดัน connection pool
- [ ] log/trace มีรหัสเชื่อมโยงเหตุการณ์ แต่ไม่มีเนื้อหาข้อความ ข้อมูลรับรอง หรือ session token

**หลักฐาน:** pipeline, digest, task revision ก่อน/หลัง, rollback, กราฟตามเวลา และการเทียบข้อความฝั่งไคลเอนต์กับฐานข้อมูล

### สัปดาห์ 6 / M6 — วัดผลเป็นขั้น ซ้อมนำเสนอ และล้างทรัพยากร

**ขึ้นกับ:** M5 และเครดิต/เวลาที่มี
**เป้าพื้นฐาน:** WebSocket พร้อมกัน 100 การเชื่อมต่อ ส่งรวม 10 ข้อความ/วินาที กลุ่มไม่เกิน 20 คน
**เป้าทดลองเพิ่มเติม:** 1,000 การเชื่อมต่อ ส่งรวม 100 ข้อความ/วินาที กลุ่มไม่เกิน 100 คน เป็นเป้าทดสอบ ไม่ใช่คำรับรองกำลังระบบ

**เกณฑ์ตรวจรับ**

- [ ] ระบุขนาด payload สัดส่วน traffic ระยะทดสอบ ผู้ใช้/อุปกรณ์ ขนาด task, pool, region และฐานข้อมูล/cache
- [ ] วัด p50/p95/p99 ของการยอมรับและการส่งถึงไคลเอนต์ ข้อผิดพลาด เวลากู้คืน backlog และทรัพยากร
- [ ] แยกแชทส่วนตัวกับกลุ่มที่ส่งถี่ จำนวน connection อย่างเดียวไม่เพียงพอ
- [ ] วัดจำนวน task คงที่ก่อน แล้วตั้ง autoscaling แบบมีขอบเขตและเปรียบเทียบผล
- [ ] scale-in ระบาย socket และคืนงาน worker ได้ ไม่สมมติว่าการเพิ่ม task ย้าย socket เดิม
- [ ] ใช้ Multi-AZ RDS ในรูปแบบสาธิต และซ้อม failover พร้อมวัดช่วงสะดุดเมื่อบัญชีและเครดิตรองรับ
- [ ] เตรียมสไลด์ เหตุผลเลือกบริการ วิดีโอ/ผลที่เก็บไว้ และบทสาธิตที่จับเวลา
- [ ] ส่งออกหลักฐาน/ข้อมูลที่อนุญาตแล้วล้างระบบ ตรวจ snapshot, EIP, log, image, secret และ bucket ที่เหลือ

**หลักฐาน:** รายงานผลที่ทำได้จริง ข้อจำกัดและความล้มเหลว แยกเป้าพื้นฐานจากเป้าทดลอง ห้ามแต่ง SLA หรืออ้างจำนวนผู้ใช้โดยไม่มีผลวัด

## สถานะรวม

M1-M6 ทั้งหมดยัง **ไม่ได้เริ่มพัฒนาและตรวจรับ** มีเพียงเอกสารแผนกับการคำนวณราคาสาธารณะ ยังไม่มีหลักฐานการทำงานของแอป บัญชี AWS, CI, deployment หรือ benchmark

## โครงสร้างโค้ดและสัญญาที่เสนอ

แยกคำสั่ง server, worker และ migrate ใช้ package ตามความสามารถ เช่น identity/session, conversation, message, recovery, realtime, delivery และ outbox มี web, migrations, infra, tests และเอกสารที่ค้นหาได้จากรากโครงการ ไม่สร้าง package ว่างเพื่อให้เหมือนแผนภาพ

HTTP ขั้นต้นครอบคลุม health ผู้ใช้ปัจจุบัน ห้องที่เข้าถึงได้ ส่งข้อความ ประวัติแบ่งหน้า และ sync ส่วน WebSocket มี subscribe/unsubscribe เหตุการณ์ข้อความและการแจ้ง restart สร้าง schema ที่ตรวจด้วยเครื่องและ error รูปแบบเดียวกันไปพร้อมแต่ละส่วน ชื่อ endpoint และค่าจำกัดเชิงตัวเลขยังเป็นรายละเอียดที่ต้องกำหนด

## งานระยะถัดไป

- หน้าจัดการกลุ่ม คำเชิญ และรายชื่อผู้ใช้ โดยคงกฎสิทธิ์ที่ตกลงแล้ว
- ตำแหน่งอ่านร่วมระดับผู้ใช้และ cursor แยกต่ออุปกรณ์ แสดงใบตอบรับการอ่านเฉพาะ DM
- สถานะกำลังพิมพ์และออนไลน์โดยประมาณ ไม่มีประวัติ last-seen
- แก้ไข/ลบข้อความพร้อมการกู้คืนเหตุการณ์เปลี่ยนแปลง
- ไฟล์แนบ ปฏิกิริยา ค้นหา push notification ห้องสาธารณะ หลาย workspace, E2EE, เสียง/วิดีโอ และเขียนหลาย region พร้อมกัน ไม่จำเป็นสำหรับเดโมนี้
