# สถานะไคลเอนต์และขอบเขตฟีเจอร์ระยะถัดไป

เลือกข้อความ immutable ใน milestone แรกและเก็บ pending sends ในเบราว์เซอร์ด้วยรหัสเดิม เพื่อ retry หลัง refresh ได้ ส่วน read receipts, typing และ presence เลื่อนไปหลังเดโมโครงสร้างพื้นฐาน

- **บันทึก:** 2026-10-28 จากข้อสรุปเดิมในบทสนทนา/Notion ไม่ใช่การตัดสินใจใหม่
- **สถานะการพัฒนา:** ยังไม่มีผลตรวจรับยืนยันในเอกสารต้นทาง

## ข้อสรุปและข้อแลกเปลี่ยน

- **D16 — ข้อความยังแก้ไข/ลบไม่ได้ใน milestone แรก:** เพิ่มภายหลังพร้อมสัญญากู้คืนการเปลี่ยนแปลง
- **D36 — เก็บข้อความรอยืนยันในเบราว์เซอร์:** ใช้รหัสเดิมหลัง refresh/retry แยกตามผู้ใช้ ล้างเมื่อ logout จัดการกรณี storage ล้มเหลว และไม่แสดงว่ารับสำเร็จก่อนเซิร์ฟเวอร์ยืนยัน
- **D37 — ตำแหน่งอ่านร่วมระดับผู้ใช้:** ขยับไปข้างหน้าอย่างเดียวต่อห้อง แต่ตำแหน่ง sync ของแต่ละอุปกรณ์แยกกัน
- **D38 — ใบตอบรับการอ่านเฉพาะ DM:** ตำแหน่งอ่านในกลุ่มเป็นข้อมูลส่วนตัวสำหรับนับข้อความที่ยังไม่อ่าน
- **D39 — กำลังพิมพ์และออนไลน์โดยประมาณ:** เป็นข้อมูลชั่วคราวหมดอายุได้ ไม่มีประวัติ last-seen และเพิ่มหลังแกนข้อความทำงานแล้ว

D37-D39 รวมถึง UI จัดการกลุ่ม/คำเชิญ/รายชื่อถูกเลื่อนจากเดโมขั้นต่ำ นโยบายยังคงยอมรับแล้ว แต่ไม่ใช่งานที่ต้องทำก่อนสาธิตคลาวด์

## เงื่อนไขที่ต้องรักษา

- IndexedDB แยกผู้ใช้และล้าง logout; storage อาจถูกล้าง จึงไม่ใช่ durable guarantee
- ผล HTTP กับ live event อาจสลับลำดับ; รวมด้วย message ID และ server order
- Read state ระดับผู้ใช้กับ recovery cursor ต่ออุปกรณ์เป็นคนละหน้าที่
- Edit/delete ในอนาคตต้องมี recovery ของการเปลี่ยนแปลง ไม่ใช้ create order เพียงอย่างเดียว
- UI สมาชิก/คำเชิญ/รายชื่อเลื่อน แต่กฎสิทธิ์ยังต้องรักษา
